LUMI Baby Tracker — personal release and rollback (offline-capable)

This runbook covers the personal app only. No family API, remote telemetry URL,
or store signing secrets are required for local care after install.

1. Staging
   - Set EXPO_PUBLIC_LUMI_ENV=staging for a labeled build.
   - Run typecheck, lint, test, and content:validate.
   - Print release evidence: npm run ops:evidence -w @maxii/baby-tracker
   - Install on a device/emulator without network if verifying airplane mode.

2. Distribution build
   - Native application ID on iOS and Android: com.matejikj.
   - After `npm run prebuild:native`, verify generated projects:
     `npm run release:verify-native -w @maxii/baby-tracker`
     (checks android applicationId/namespace and iOS PRODUCT_BUNDLE_IDENTIFIER).
   - export:android / export:ios only export JavaScript and assets; they do not produce an installable native release.
   - Android personal APK (local toolchain):
     `npm run release:android -w @maxii/baby-tracker`
     Keystore defaults to ~/.lumi-signing/personal-release.keystore (created on
     first run). Override with LUMI_UPLOAD_STORE_FILE / _PASSWORD / _KEY_ALIAS /
     _KEY_PASSWORD or LUMI_SIGNING_DIR. Keys never enter git.
   - Record the installable Android APK and store AAB separately; an AAB is not installed directly on a device. For iOS, record the signed archive/export or distributed TestFlight build (requires a local Apple signing identity).
   - export:web produces the static web files; verify with `npm run release:web`
     (service worker activation and offline restart in a supported browser).
   - Keep signing keys and store credentials outside the repository.
   - Record the printed release evidence with the binary hash in your release log.
   - Never uninstall the previous app as an automated build step. A different application ID has separate data and needs a verified portable export/import path.
   - Candidate checklist helper: `npm run release:candidate -w @maxii/baby-tracker`
     (evidence print + `release:gate` + native id verify + web export/e2e).
     Android APK remains a separate `release:android` step so signing stays explicit.
   - After an APK exists, `npm run release:gate -w @maxii/baby-tracker` also checks
     aapt package/version/permissions and prints the APK sha256.
   - Emulator care matrix (airplane install, diaper/bottle/note/growth, Rozvoj,
     force-stop, Historie):
     `npm run release:android:care-matrix -w @maxii/baby-tracker`

3. Progressive publish
   - Ship to an internal track first.
   - Confirm: cold start, diaper save, restore from checkpoint, diagnostics export.
   - Only then widen the rollout.

4. Migration health
   - Opening the app applies pending migrations behind a checkpoint.
   - If a checkpoint cannot be written, migration must refuse to start.
   - After upgrade, confirm schemaCompatibility in the support report matches the binary.

5. Rollback
   - Do not install an older binary over a newer diary schema.
   - The app refuses schemas newer than its native/web compatibility ceiling.
   - Keep a verified portable diary export and the original compatible build available before changing versions.
   - Restore into an older build only if that build supports the archive/schema being restored; otherwise use a compatible fixed build. A backup does not make an incompatible downgrade safe.
   - Never rely on silent schema downgrades.

6. Support
   - Caregivers export a redacted support report from Settings → Diagnostika.
   - The report never attaches the diary backup automatically.
   - Canary note/DOB values must remain redacted in logs and the report.

7. Outage of cloud tools
   - Build/distribution tooling is not the product backend.
   - After install, care, recommendations, history and local export work without those services.
